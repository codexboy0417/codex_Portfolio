CORE FRAMEWORK
  astro ^5.5.5
    — Static site generator. Builds final HTML/CSS/JS. Handles routing,
      layouts, pages, and integrations. Output mode: "static" (no server).

  react 18.3.1
    — UI component layer inside Astro. All interactive sections
      (Hero, About, Skills, Projects, Contact, Intro animation) are
      React components mounted as Astro islands.

  react-dom 18.3.1
    — Required alongside React for DOM rendering.

  @astrojs/react ^4.4.0
    — Astro integration that enables React components inside .astro files.

BUNDLER & BUILD
  vite ^6.4.1 (pinned to 6.3.5 via pnpm override)
    — Underlying bundler used by Astro. Handles hot module replacement,
      asset processing, TypeScript compilation, and production bundling.

  @vitejs/plugin-react 4.7.0
    — Vite plugin enabling React JSX transform in the Vite pipeline.

STYLING
  tailwindcss 4.1.12
    — Utility-first CSS framework. All layout, spacing, color, and
      typography classes are Tailwind utilities.

  @tailwindcss/vite 4.1.12
    — Tailwind 4's native Vite plugin (replaces PostCSS config).

  tw-animate-css 1.3.8
    — Pre-built Tailwind-compatible animation keyframes.

  class-variance-authority 0.7.1
    — Type-safe utility for composing Tailwind class variants.

  clsx 2.1.1

  tailwind-merge 3.2.0

4. HOW THE SITE WORKS — ARCHITECTURE
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

RENDERING PIPELINE:
  1. Astro compiles all .astro pages at build time → static HTML
  2. React components are hydrated client-side where needed
  3. Vite bundles all JS/TS/CSS into optimized chunks in dist/_astro/
  4. Vercel serves the dist/ folder with custom cache headers

PAGE FLOW:
  Browser loads / → index.astro → BaseLayout.astro wraps it
  → <App client:load /> mounts React
  → IntroSplash renders on top (full screen, z-50)
  → User dismisses splash → App reveals all sections
  → Sections: Hero → About → Skills → Projects → Contact

SPATIAL MODEL (3 layers):
  Layer 1 — Fixed Background: A pure black (#070707) room-tone background.
             Stays fixed behind everything.
  Layer 2 — Particle Field: Ambient floating particles on a canvas element.
             Independent motion, provides depth illusion.
  Layer 3 — Scrollable Content: All actual sections scroll over layers 1 & 2.
             Gives the "moving through space" UX feel.

STATE MANAGEMENT:
  No Redux or external state library. All state is local React useState/useRef.
  - IntroSplash: local `dismissed` boolean
  - Projects: local `openId` string for accordion
  - Contact form: local `status` ("idle" | "sending" | "sent" | "error")
  - CornerHUD: local timer ref + mouse event listener

MOTION PATTERNS USED:

1. Scroll-reveal (whileInView)
   Elements animate from { opacity: 0, y: 24 } to { opacity: 1, y: 0 }
   when they enter the viewport.
   viewport={{ once: true }} → plays only on first scroll past
   transition: { duration: 0.5, ease: "easeOut" }

2. Staggered children (variants + staggerChildren)
   Parent container has staggerChildren: 0.08 in transition
   Each child animates with a delay offset
   Used in: Hero chips, About pillars, Skills cards

3. AnimatePresence (mount/unmount transitions)
   Used in Projects accordion: card detail section fades + slides in/out
   initial={{ opacity: 0, height: 0 }}
   animate={{ opacity: 1, height: "auto" }}
   exit={{ opacity: 0, height: 0 }}

4. useMotionValue + useTransform (pointer parallax)
   In Hero: tracks mouse X/Y as motion values
   Text layers have different transform ratios (depth simulation)
   Layer 1 (name): moves -8px to +8px
   Layer 2 (photo): moves -4px to +4px (half speed = "further")
   Layer 3 (chips): moves -12px to +12px (faster = "closer")

5. useSpring (smooth easing)
   Applied to motion values to add spring physics
   stiffness: 100, damping: 20 → smooth but responsive

6. Card tilt (3D perspective on hover)
   onMouseMove calculates mouse position relative to card center
   rotateX and rotateY applied as style transforms
   perspective: 1000px on parent
   Resets smoothly on mouseLeave with transition: { duration: 0.5 }

7. Reduced motion:
   prefers-reduced-motion media query checked via window.matchMedia
   Particle animation slows to minimal drift (no jitter)
   Scroll reveals still run but with shorter duration

File: src/app/components/IntroSplash.tsx

Purpose:
  Full-screen cinematic intro animation that plays once when the site loads.
  Shows the text "codexboy_04" assembled from drifting particles.
  User dismisses it by scrolling, pressing any key, touching, or clicking.

CANVAS SETUP:
  Two canvases are used:
    offscreenCanvas (octx) — hidden, used only for text measurement/rasterization
    mainCanvas (ctx) — visible fullscreen, displays particle animation

  DPR-aware rendering:
    const dpr = window.devicePixelRatio || 1
    canvas.width  = w * dpr
    canvas.height = h * dpr
    ctx.scale(dpr, dpr)
  This ensures crisp rendering on Retina/HiDPI screens.

FONT HANDLING:
  Font family: "DM Sans", sans-serif
  Weight: 700 (bold)
  Base font size: 10% of min(width, height)

  Auto-shrink to fit any screen width:
    const maxWidth = w * 0.86
    const measured = octx.measureText(TEXT).width
    if (measured > maxWidth) {
      fontSize = fontSize * (maxWidth / measured)
      octx.font = `700 ${fontSize}px "DM Sans", sans-serif`
    }
  This guarantees the text is never clipped on small screens (mobile).

  Font load wait:
    document.fonts.ready.then(() => { initParticles() })
  Prevents rendering before DM Sans is loaded (no fallback font particles).

TEXT:
  TEXT = "codexboy_04"
  Color: rgba(232, 224, 208, 0.92)  ← warm off-white, 92% opacity

PARTICLE SAMPLING:
  1. Draw text onto offscreen canvas with white fill
  2. Read pixel data: octx.getImageData(0, 0, ow, oh).data
  3. Every 3rd pixel: if alpha > 128 → that pixel is "inside the text"
  4. Store its canvas (x, y) position as a target point
  This gives a list of target positions forming the text shape.

PARTICLE OBJECT STRUCTURE:
  Each particle has:
    x, y    — current canvas position (starts scattered randomly across screen)
    tx, ty  — target position (inside the text shape)
    size    — random 1.0–1.7px radius
    alpha   — random 0.55–0.95 (varied brightness)
    speed   — random 0.04–0.08 (varied easing rate)

PARTICLE COUNT:
  Sampled from the text pixel data (every 3rd pixel at ~86% of viewport).
  Typically 1500–4000 particles depending on screen size and font size.

ANIMATION LOOP (requestAnimationFrame):
  Each frame:
    1. Clear canvas: ctx.clearRect(0, 0, w, h)
    2. For each particle:
       a. Calculate ease = 1 - Math.exp(-elapsed / 1200)
          — Exponential ramp from 0 to 1 over ~1.2 seconds
       b. Calculate jitter = (1 - ease) * 0.3
          — Jitter starts at 0.3 and fades to 0 as ease approaches 1
          — This makes early motion feel alive/scattered, settles to precise
       c. Update position:
          p.x += (p.tx - p.x) * 0.06 * ease + (Math.random() - 0.5) * jitter
          p.y += (p.ty - p.y) * 0.06 * ease + (Math.random() - 0.5) * jitter
          — Spring-like: always pulled toward target, slows as it arrives
          — Jitter term is random displacement ±0.15px (fades to 0)
       d. Draw particle:
          ctx.globalAlpha = p.alpha
          ctx.beginPath()
          ctx.arc(p.x, p.y, p.size, 0, Math.PI * 2)
          ctx.fill()

JITTER FADE PHYSICS:
  This is the key difference from the broken first version.
  In the old version, mouse proximity caused white flares and shake.
  The new version uses jitter that is tied to the assembly progress (ease).
  When ease = 0 (start): jitter = 0.3 (scattered, alive)
  When ease = 1 (assembled): jitter = 0 (perfectly still)
  No mouse tracking. No proximity effects. Pure mathematical settling.

DISMISSAL:
  Event listeners on document:
    scroll  → dismiss()
    wheel   → dismiss()
    touchstart → dismiss()
    keydown → dismiss()
    click (after 600ms delay to avoid accidental dismiss) → dismiss()

  dismiss():
    Sets dismissed state → triggers fade-out CSS transition
    After 500ms: removes IntroSplash from DOM entirely

FADE OUT:
  CSS opacity transition: opacity: 0, transition: opacity 0.5s ease
  Applied when dismissed=true

MOBILE HANDLING:
  Same component, same canvas.
  Font auto-shrink (86% max width) ensures it fits on 360px wide phones.
  No mouse parallax (no mouse on touch devices).
  Touch event triggers dismissal.

19. KNOWN QUIRKS & NOTES
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

1. FIRST BUILD TAKES LONGER
   sharp (image optimizer) needs to compile native bindings.
   Subsequent builds are faster (cached).

2. DM SANS MUST LOAD BEFORE INTRO
   IntroSplash calls document.fonts.ready before sampling text pixels.
   If fonts fail, the fallback sans-serif renders (still looks fine).

3. INTROSPLASH DISMISS CLICK DELAY
   The click-to-dismiss listener is added after 600ms to prevent
   accidental dismissal on the initial click that loads the page.

4. PARTICLE COUNT SCALES WITH SCREEN SIZE
   Bigger screens → larger rendered text → more sampled pixels → more particles.
   On small phones: ~1000 particles. On large monitors: ~4000.

5. CornerHUD TIMER RESETS ON RELOAD
   It is a session-start timer (from component mount), not a clock.
   Expected behavior.

6. vercel.json rewrites are SPA rewrites, not 301 redirects.
   Typing ashit-upadhyay.vercel.app/projects goes to / and
   scrolls to the Projects section via JS (no separate page exists).

7. ASTRO OUTPUT IS FULLY STATIC
   No Node.js server required. All pages are pre-rendered HTML.
   Vercel serves it from CDN (edge network globally).

8. CONTACT FORM BACKEND
   The contact form POSTs to a Vercel serverless endpoint or a configured
   form service. Ensure a backend is set up for it to actually send emails.
   Without backend: the form will show an error state on submit.
